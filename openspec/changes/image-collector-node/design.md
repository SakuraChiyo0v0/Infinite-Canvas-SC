## Context

智能画布使用浏览器运行串行/并行循环，异步任务和图片节点一起持久化。后端已有本地资源解析和分组导出能力，但分组导出不具备逐张结果状态及跨请求防覆盖。

## Goals / Non-Goals

**Goals:** 仅显式连接时收集；普通生成与循环均可使用；逐张保存、失败重试、不覆盖文件；节点数量不随完成的图片增加。

**Non-Goals:** 普通画布、视频收集、无人值守后台循环、修改生成服务输出路径。

## Decisions

- 新建 smart-collector 终点节点。连线仅接受图片或智能分组来源，不参与图片生成链路遍历，不提供输出端口。
- 使用独立前端模块处理收集记录、保存队列和节点 UI；在现有输出完成入口分发新图片。
- 已连接收集器的单次/循环输出使用不显示的临时任务槽，保持现有异步恢复机制；完成后移除任务槽，结果仅保存在收集记录中。未连接时完整沿用原节点路径。
- 保存接口在后端解析已知本地资源或使用现有远程媒体下载能力；核实实际图片格式。用户显式填写后端机器的绝对目录，文件名前缀不允许路径成分。
- 使用稳定的记录 ID 与批次/序号命名，独占创建文件；同一保存请求重试幂等，既有文件不覆盖。保存失败保留 URL 与错误，不重新请求生成。
- 保存状态与记录存入画布，缩略图默认仅显示最近 6 张；完整列表分页查看。生成开始时固定收集目标，防止运行中改线丢失结果。

## Risks / Trade-offs

- 浏览器关闭会停止新循环调度 → 沿用现有任务恢复能力，不声称后台调度。
- 文件保存成功但响应丢失 → 稳定记录 ID 保证重试不产生重复文件。
- 大批次 DOM 增长 → 仅有限缩略图和分页记录进入 DOM。
- 生成与保存失败不同 → 单独显示保存失败及重试操作；无效目录可修正后重试。

## Migration Plan

仅新增节点类型及接口，旧画布无需迁移；不连接即保持旧行为。仓库存在其他未提交工作，增量修改，不提交或覆盖无关文件。
