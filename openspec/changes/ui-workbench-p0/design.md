## Context

项目是 FastAPI + 静态 HTML/JS + iframe 外壳的结构，不引入前端框架。图片工具页共用 `cli-image-tools.js` 提供的服务选择与尺寸控件。仓库当前处于一次未提交的上游合并状态（`codex/gpt-image2-fix` 上合并 `67f49e4`）。

## Goals / Non-Goals

目标：先立基础可读性规范，再用文生图样板页验证，最后推广。
不包含：其余图片工具、素材库、画布管理、对话页的改造；深色模式专项、无障碍全流程、真实计费生图。

## Decisions

- 缩放：`theme.js` 删除按窗口尺寸取最小值（最低 0.68）的 `autoScale` 与按内容宽度收缩的 `contentFit` 逻辑，缩放选项收敛为手动百分比，默认 100%。画布/网格自身的 zoom/pan 是另一套坐标逻辑，保持不动。
- 令牌：以 `--ui-*` 前缀定义在 `theme.css` 的 `:root` 与暗色覆盖中，避免与页面既有的 `--bg`/`--text` 等局部变量冲突。
- 导航：只保留 `is-pinned` 一种展开来源（由显式按钮切换并写入 `studio_sidebar_pinned`），删除全部 `.sidebar:hover` 展开规则与 `is-collapsing` 过渡抑制逻辑；折叠态用 `title` 提示入口名称。
- 文生图：保留原有三个引擎分支与请求字段，仅在布局层重排；历史网格与灯箱逻辑不变，新增结果视图以展示最近一次结果。
- 降级策略：窄容器下参数区与结果区纵向排列，主操作紧跟在参数之后，保证首屏可达。
- 参数栏高度分配：参数区 `flex: 0 1 auto`，不主动撑高。参数少时主按钮直接跟随控件，剩余空白留在栏位底部（常见侧边栏形态）；参数多时参数区自然占满并滚动，主按钮固定在底部。避免"参数挤在顶部、按钮吊在底部、中间一大片空洞"。
- 提示词输入区固定 160px（规范 120–160px），不参与高度分配；不要为了填满栏位把输入框拉成数百像素高。
- 词条缓存：i18n 词条模块由 `i18n.js` 用写死的版本号拼 URL 加载，`/static/*.html` 下的资源版本号又只在服务启动时刷新一次，因此"改了词条但浏览器仍用旧文件"会把 `studio.xxx` 这类 key 直接渲染到界面上。凡改动词条文件，必须同时提升 `i18n.js` 的 `VERSION`，并刷新各页面中 `/static/**` 资源引用的 `?v=`（与服务启动时的行为一致）。

## Risks / Trade-offs

- 取消自动缩放后，未迁移的页面可用宽度减少约 64px（1440 宽下），可能出现局部换行 → 已实测 1440/743 两个宽度下各页无横向溢出，剩余页面的紧凑度问题留待 P1 迁移。
- 导航折叠态默认不展开，入口名称只能通过 hover 提示 → 已通过 `title` 与显式展开按钮补偿。
- 结果视图复用历史第一条作为初始展示 → 与"结果优先"一致，但不代表本次生成。

## Migration Plan

无需数据迁移。界面缩放键 `studio_ui_scale_mode` 中的旧值（如 `auto`）会被规范化为 100%，不影响其他本地数据。
