## Context

用户已确认首版实施，代码及本地验收已完成。真实模型审核、分类和分支跳过证据见 `verification.md`。

设计时的代码基线：
- `static/js/canvas.js` 的 `callCanvasLLM`、`llmInputImages` 和 `main.py` 的 `/api/canvas-llm` 已支持图片输入；现有接口返回文本，没有经过校验的分支结果。
- `canvasWorkflowEdges`、`computeCascadeOrder`、`runNodeCascade` 按节点依赖和固定轮数运行。连线主要为 `{id, from, to}`，没有出口标识；`canConnect` 和 `sanitizeConnections` 也需要识别新节点。
- `static/js/smart-canvas.js` 有另一套循环、连线和运行状态实现。已确认首版以无限画布为入口，避免同时维护两套新调度行为。
- 现有运行态会写到共享节点及 `loopContext`。这不能直接充当并行分支结果的隔离边界；这里只指出新功能的设计约束，不认定现有实现已经发生串轮故障。
- `canvas_workflow_payload` 当前输出版本 1；导入导出、复制及连接清理均需保留新字段。

## Goals / Non-Goals

**Goals:**
- 用户填写判断要求即可把图片送到正确的后续步骤，并能看到依据。
- 支持审核及分类，每次只选一个出口；默认保留原图，按需传递修改建议。
- 区分模型无法判断、图片不符合要求、请求或解析失败。
- 固定次数循环的每轮使用独立图片、判断结果和分支状态。

**Non-Goals:**
- 自动回连重生成、分支汇合、嵌套循环、视频审核、多图比较和自动逐图拆分。
- 独立人工挑选节点、独立预览节点、智能画布适配及本地模型安装。
- 后台持久运行与刷新后自动续跑；首版遵循前端驱动运行的边界。

## Decisions

### 1. 产品形态：一个“视觉判断”节点，两种模式

审核模式为默认，固定三个出口：通过 `pass`、不通过 `fail`、无法判断 `unknown`。用户输入自然语言标准；默认所有要求满足才通过，明确违反任意要求则不通过，证据不足且没有已确认违反项才无法判断。

分类模式允许 2–6 个自定义类别，每项包含稳定 ID、名称和描述，额外保留不可删除的 `unknown`。按类别列表顺序匹配，多个类别适用时选择首个满足者；要求互斥分类时用户可在描述中进一步限定。类别改名、排序不会改变 ID，删除已连线类别前展示会移除的连线数量。

两种模式共享同一节点与后端结果结构，比拆成审核和分类两个节点更容易理解。切换模式会影响出口，存在连线时需要明确展示影响后再执行。

### 2. 节点界面及交互

```text
┌ 视觉判断                       待运行 ┐
│ 图片输入 ●  [本轮图片缩略图]          │
│ 模型      [服务商 / 模型          ▾] │
│ 模式      [审核] [分类]              │
│ 判断要求                            │
│ ┌ 人物完整入镜，穿红色外套，       ┐ │
│ │ 不含明显文字。                   │ │
│ └─────────────────────────────────┘ │
│ [测试判断]          [运行此流程]     │
│ 本轮结果：不通过                     │
│ 依据：人物脚部超出画面。             │
│ 修改建议：扩大取景，完整展示全身。   │
│                             通过 ● │
│                           不通过 ● │
│                         无法判断 ● │
└────────────────────────────────────┘
```

- 输入端首版每轮接受一张待判断图片，来自上传、已有输出或本轮上游生成结果；多张输入明确报出数量并要求选一张或调整现有循环，不自动选择最后一张。
- “测试判断”仅消费已存在图片，不启动上游或下游；按钮旁说明会调用一次所选模型。
- “运行此流程”执行所属工作流的上游和可达分支，运行中变为停止；不因点击位置不同遗漏兄弟分支。
- 结果区显示本轮缩略图、命中出口、简短依据、修改建议、模型和耗时；提供轮次切换。依据是简短结论解释，不请求模型内部推理过程。
- 分支使用文字标签与线条状态共同表达，不能只靠颜色。出口支持键盘聚焦与选择连接目标；运行结果通过可访问状态区提示。
- 未连线的命中出口正常结束本轮，并显示“命中此分支，未连接后续步骤”。`unknown` 默认也如此；不伪装成人工审批暂停。
- 修改图片、判断要求、模式、类别或模型后，旧结果标注“历史结果，需重新判断”，不能再驱动执行。运行期间冻结本次配置快照。

### 3. 分支传递的内容

每次判断生成一个结果包：原图引用、`branchId`、`reason`、`suggestion` 和运行元信息。一个命中出口可以连接多个节点，所有直接下游都收到同一张原图；不命中出口不产生本轮数据。

出口连线默认仅传图片；连接到有文本输入能力的节点时，连线设置允许选择“同时附加修改建议”或“同时附加判断依据”，对应 `textField: none | suggestion | reason`。附加内容放在已有提示词之后，不覆盖用户原有提示词。图片输出节点只展示原图。

首版不要求通用类型系统，适配现有图片输入与提示词读取边界即可；不允许下游从节点历史显示值读取本轮数据。

### 4. 后端接口：新增严格契约，复用模型传输

新增 `POST /api/canvas-vision-judge`，保留 `/api/canvas-llm` 的自由文本行为。复用现有服务商解析、图片转换、HTTP 超时和错误映射，不直接把普通对话文本当作判断结果。

请求示意：

```json
{
  "provider": "configured-provider-id",
  "model": "configured-vision-model",
  "image": "/output/example.png",
  "mode": "review",
  "instruction": "人物完整入镜，穿红色外套，不含明显文字。",
  "branches": [
    {"id": "pass", "label": "通过", "description": "全部要求满足"},
    {"id": "fail", "label": "不通过", "description": "存在明确违反项"},
    {"id": "unknown", "label": "无法判断", "description": "证据不足"}
  ]
}
```

成功返回示意：

```json
{
  "branchId": "fail",
  "reason": "人物脚部超出画面。",
  "suggestion": "扩大取景，完整展示全身。",
  "model": "configured-vision-model",
  "usage": null
}
```

- 服务端要求合法模式、非空判断要求、恰好一张可读取图片；审核出口由服务端固定验证，分类 ID 必须唯一，数量 2–6 且包含额外 `unknown`。限制指令为 4000 字、类别名 40 字、类别描述 500 字。
- 结果必须是单个 JSON 对象，`branchId` 在允许集合内，`reason` 为 1–1000 字文本，`suggestion` 为最多 2000 字的文本（可为空）。不接受多分支、未知 ID、额外执行字段或缺失字段。不从自由文本猜分支。
- 可去除完整包裹 JSON 的 Markdown 代码围栏，除此之外解析失败即失败；不静默调用模型进行格式修复，也不自动重试。
- 支持结构化输出的服务商可使用其已验证能力；未验证服务商以固定 JSON 提示词加服务端校验工作，不默认发送所有服务商都接受的 `response_format`。
- 提示词把图片文字视作待检查内容，不允许它改写出口集合。前端把结果当文本展示，不执行 HTML、表达式或代码。
- 首版接现有 API 多模态调用路径，包括用户配置的本地兼容地址；模型名称只作提示，不能证明视觉支持。“测试判断”验证实际兼容性，不兼容时显示错误，不静默换模型或降级为纯文本。CLI 路径不纳入首版。
- 不提供未经校准的置信度阈值或默认“质量分”；用户的自然语言标准决定分支。

### 5. 执行计划：先判断，再激活下游

包含视觉判断节点的连通工作流使用分支调度；不包含它的流程保留当前执行方式。任一此类流程运行入口都显示“运行此流程”，在调用前完成整个连通工作流检查，明确这是整条流程而非只运行选中的末端。

1. 解析图片和文本依赖、输出中转节点及出口 ID，建立无环执行计划；静态输入仍是依赖，但不需要调用模型。
2. 拒绝回连、分支汇合、多个循环控制器、悬空出口或不支持的连接；保留有问题的导入内容并显示定位信息，不静默删线。
3. 同一判断节点不同出口的后代集合不得相交，即使通过输出节点中转也一样；共享静态素材不属于分支汇合，允许多个分支读取。
4. 共同上游每轮只执行一次，轮到判断节点时调用视觉模型。
5. 只激活命中出口，其余出口所属节点标为 `skipped`；不读取这些节点的历史输出。活动节点的其他输入依赖仍须满足。
6. 多个判断节点可以沿单向分支串联；它们各自判断，不允许形成回路或跨出口汇合。
7. 命中出口可连接多个后续操作，首版同轮按确定顺序执行；一个活动节点失败则停止该运行后续调度，不继续发起其他付费调用。

不选择“先执行所有下游再隐藏未命中结果”，因为这会浪费模型调用且不符合条件分支含义。不选择立即替换全部执行器，降低对已有流程的影响。

### 6. 固定循环、运行隔离与异常处理

- 支持现有固定次数循环，每轮恰好一张判断图片；生成节点每次产生多图时运行前可预检的提前提示，运行时发现则报错，不默默拆批。
- 运行上下文使用 `{runId, roundId, nodeId}` 定位输出，包含配置快照、状态、分支结果和输出映射；传入执行函数，不依靠全局 `loopContext` 或共享 `node.outputText` 做分支决策。
- 串行逐轮执行；并行沿用现有并发上限，每轮上下文独立。共享节点字段只用于展示，按轮次查看历史，不作为调度数据源。
- 正常“不通过”或“无法判断”仍是一次成功判断，继续对应分支。HTTP 错误、图片读取失败、超时、返回格式错误是 `failed`，不激活任何出口。
- 停止后不再派发节点，取消前端可取消请求；已到达外部服务的请求不保证停止或免计费。迟到响应不能改变已停止运行或后续新运行。
- 手动重试失败节点时，新建该轮尝试标识，复用本轮已完成上游输入，从失败节点及其尚未完成后继继续，不重复执行本轮已成功的兄弟分支；之前成功的其他轮保持不变。配置变化则必须启动新运行。
- 刷新页面后保留可展示结果，把未完成运行标记为中断，不自动续跑。首版提供当前运行各轮记录及最近一次结果，不承诺永久保存完整运行历史。

### 7. 数据与兼容

节点增加 `type: visionJudge`、`judgeVersion: 1`、`provider`、`model`、`mode`、`instruction`、`branches`。连线新增 `fromPort` 与 `textField`；普通旧连线缺省按原有输出处理，但视觉节点的出口必须显式存在。

- 新前端读取旧画布无需迁移已有节点；保存、复制、撤销重做均保留新字段，复制仅重映射节点和连线 ID，类别 ID 不变。
- 普通工作流继续按版本 1 导出；包含视觉判断节点的工作流按版本 2 导出，并声明 `requiredFeatures: ["vision-judge-v1", "conditional-routing-v1"]`。
- 新导入器检查版本和能力，支持版本 1 与此次版本 2。未知必需能力拒绝导入，不丢弃后继续执行。
- 无法保证旧客户端识别新文件，因此版本 2 导出入口明确提示需要支持视觉判断的新版本；不声称旧客户端能安全降级。
- 不把凭证写入节点、结果或工作流，仅保存服务商 ID 与模型名；缺失服务商时要求重新选择。
- 后端和前端分别验证输入；用户导入的文件不能绕过连线或结果约束。

### 8. 示例及后续阶段

首版审核：`循环 6 次 → 生成单图 → 视觉判断 → 通过：放大 / 不通过：另一个生成节点按建议重画一次 / 无法判断：输出原图待查看`。另一个生成节点是单向后继，不回连原生成节点；首版不自动再次检查重画结果，用户可手动再接一个判断节点。

首版分类：`上传单图 → 视觉判断 → 人像：人像处理 / 风景：风景处理 / 商品：商品处理 / 无法判断：输出原图`。

下一阶段另立提案设计“生成—判断—重试”受控区块：默认最多重试 2 次（总计 3 次生成），通过则提前结束；达到上限交给用户查看。范围需包括重试次数、预算提示、建议如何并入提示词、保留每次结果、停止和恢复，不以普通连线形成无限回路。

## Risks / Trade-offs

- 模型判断不稳定、细节漏检 → 展示原图与简短依据；默认不包装成客观质量分，保留无法判断出口。
- 图片转换缩小后难以检查小字或手部 → UI 标注判断基于发送给模型的图片；先使用现有图片转换上限，精细审核及多图比较后续单独评估。
- 并行轮次污染 → 分支上下文独立，必须覆盖交错返回与迟到响应测试。
- 改动涉及调度和输入读取 → 新路径只作用于含视觉判断的流程，同时回归普通 LLM、输出中转和原有循环。
- 多出口汇合语义复杂 → 首版禁止，明确指向冲突节点；后续通过专门汇合节点设计。
- “本地画布”不等于模型离线运行 → 显示实际服务商，使用云端服务时图片照常发给所选服务商。

## Migration Plan

实施时先完成结果契约和分支计划的独立模块，再接后端与画布 UI，最后接循环和导入导出。用已有画布副本验证，不覆盖用户原文件。发布前用用户现有配置验证至少一个支持图片的模型；未完成时明确标注仅完成模拟验证。

回退代码前保留含新节点的画布副本；旧版本仅操作没有新能力的副本，避免旧清理逻辑删除新连线。这里是未来实施和发布方案，不构成本轮发布授权。

## Scope and Verification Decisions

- 首版入口为无限画布；智能画布的独立调度适配需另行确认范围。
- 用户未另行指定验收模型，告知后使用画布当前默认的 AI Gateway / Codex/gpt-6-astra，以自行生成的非敏感色块图完成真实审核与分类验证。
- 自动返工属于下一阶段，未包含在首版任务中。
