## Why

画布已有循环和可接收图片的 LLM 节点，但模型回复不能直接决定工作流执行哪条分支。新增视觉判断节点，让用户用自然语言检查或分类图片，自动把原图传给对应的后续流程。

## What Changes

- 在「无限画布」增加视觉判断节点，提供审核模式（通过、不通过、无法判断）和分类模式（2–6 个自定义类别、无法判断）。
- 配置图片、视觉模型和判断要求，展示本次输入缩略图、命中分支、简短判断依据和修改建议。
- 每次判断只命中一个出口；该出口可以连接多个后续节点。未命中分支显示为已跳过，不执行、不消耗生成额度。
- 增加分支感知的运行方式，与现有固定次数循环衔接，按本轮本图独立保存结果。
- 完整保存、复制、导入导出分支配置；旧画布和普通 LLM 的语义保持兼容。

## Capabilities

### New Capabilities

- `visual-judge-node`: 视觉判断节点的配置、结构化判断、结果展示与模型调用。
- `canvas-conditional-routing`: 分支连线、调度、运行隔离、停止及持久化兼容。

### Modified Capabilities

无。当前主规范没有覆盖画布分支调度的能力。

## Impact

- 前端：`static/canvas.html`、`static/js/canvas.js`、画布样式与翻译资源；建议把判断结果校验与分支计划计算放入独立模块，避免继续扩大主文件。
- 后端：`main.py` 中模型调用、画布工作流导入导出边界；计划新增 `/api/canvas-vision-judge`，复用现有服务商配置与图片引用转换。
- 数据：节点增加类型与判断配置，连线增加稳定的出口标识；仅含新能力的工作流使用新版导出格式。
- 验证：结果格式校验、分支跳过与多轮隔离、停止和重试、旧画布回归、持久化及界面验收。

## Non-goals

- 用户已确认首版实施；本次完成本地实现与验收，不提交、不推送、不部署。
- 首版不扩展智能画布，不新增独立人工挑选或图片预览节点。
- 首版不提供回连上游自动重生成、嵌套循环、批量图片自动拆分或分支再次汇合；未来单独设计受控重试与汇合语义。
- 不安装本地模型；可使用经验证能接收图片的已有 API 服务商，包括用户配置的本地兼容服务。CLI 适配本期不包含。
