## Context
数据用数组保存库、分组、条目，但管理端强制系统库置顶，普通库会过滤内置分组，部分使用端缓存分组。
## Goals / Non-Goals
实现三个层级持久排序、跨组跨库移动、使用端联动。保留现有正文与创作记录，不新增分类体系。
## Decisions
- 新增单操作移动接口，以已有数组顺序为准，不接收客户端整份数据覆盖。
- 请求携带 updated_at，过期操作返回 409；服务端验证目标、只读状态、锚点和 ID 冲突后保存。
- 库拖到库、分组拖到分组按上/下半区前后插入；分组拖到库末尾；提示词拖到提示词排序、拖到分组归组、拖到库的未分组。
- 分组跨库时连同条目迁移，目标分组 ID 冲突则分配新 ID，不隐式合并同名组。
- 首次跨库移动记录 workbench_key，稳定指向原草稿/效果图/配方，避免复制文件和并发任务中断。
- 所有使用端读取 API 数组顺序；已打开选择器通过同源通知刷新，重新打开也强制读取最新数据。
## Risks / Trade-offs
- 拖拽与框选冲突 → 批量管理状态禁用条目拖拽。
- 旧系统库空分组会被补回 → 显式空列表保留，仅缺少字段时初始化。
- 搜索结果排序 → 按可见目标 ID 定位，不用过滤后的数组下标覆盖全局顺序。
