## Context

三个本地图片工具使用共享选择器读取 `/api/providers`，但选择器只接受三种 CLI 协议。后端的 `/api/online-image` 已能根据提供商 ID 和协议发送请求，因此已配置图像模型的自定义 API 不需要新增路由。

## Goals / Non-Goals

**Goals:**

- 让用户新增的、已启用的图像 API 与 CLI 提供商一起成为可选来源。
- 避免把 ModelScope、RunningHub、火山引擎重复显示为“自定义 API”。

**Non-Goals:**

- 不改变 API 设置页的提供商配置形式。
- 不自动验证自定义 API 上游是否支持图像编辑或参考图。
- 不改变本地、ModelScope 或 CLI 的请求协议。

## Decisions

- 共享选择器将“用户自定义”定义为 ID 不属于内置远程平台集合、且已启用并至少有一个图像模型的提供商；三种 CLI 协议仍始终符合条件。该规则无需引入新的持久化字段，也能适配 OpenAI 兼容和其他已支持协议。
- 复用现有 `/api/online-image` 请求路径。该路径已根据提供商配置分发协议、模型和参考图；前端只扩展候选列表。

## Risks / Trade-offs

- [自定义服务不支持参考图或图像编辑] → 后端会返回上游错误；用户可在 API 设置中调整模型或端点。
- [内置平台 ID 被手工复用] → 该条目按内置平台处理以避免界面重复；用户应使用新的自定义 ID。
